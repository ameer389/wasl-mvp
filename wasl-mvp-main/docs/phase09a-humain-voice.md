# WASL · تقرير Phase 09A

## A. القرار التنفيذي

**VERIFIED.** سجّل HUMAIN بدء جلسة WASL الحية وانضمام الوكيل وانتهائها. أكد الفريق الحوار السعودي والإدخال الحقيقي بالميكروفون وتنفيذ أداة قراءة ومطابقة الرد مع WASL وتحرير الميكروفون. **إعادة إنتاج الاعتماديات متحققة** باستخدام `npm ci` في نسختين نظيفتين.

## B. إعادة إنتاج الاعتماديات

- البيئة هي Windows، وNode `24.19.0` وnpm `11.17.0`. يستخدم CI الحالي Node 24 على Ubuntu و`npm install --no-audit --no-fund`. بقي تكوينه كما هو.
- أعاد `npm ci --offline` على نسخة Phase 08 خطأ `EUSAGE` بسبب غياب مدخلي `@emnapi/core` و`@emnapi/runtime` في جذر lockfile. الربط الاختياري `@rolldown/binding-wasm32-wasi@1.2.19` يطلب النسختين `2.0.0-beta.2` ويستخدم `@napi-rs/wasm-runtime@1.2.6` الذي يحتاجهما كـpeers. نسختا Tailwind المضمّنتان على المسار المتداخل (`1.11.3`) خارج نطاق حل هذه peers.
- نجح تحديث metadata فقط بـ`npm install --package-lock-only --ignore-scripts` في نسخة معزولة بعد إتاحة الاتصال بسجل npm. أضيف مدخلا `2.0.0-beta.2` مع integrity وoptional metadata، وطُبّعت أعلام `peer` دون ترقية أو حذف أي حل سابق. ثم نجح `npm ci` على الرسم المصحح قبل إضافة المُزوّد (67 حزمة).
- سجل npm لم ينشر `@humain-voice/agent@0.18.1` المعروض في مسار التوثيق وقت الفحص (E404). ثُبّت الإصدار الرسمي المنشور `0.20.0` والتحقق من تعريفاته ومصدره المركّب. يصرح بـpeer `livekit-client ^2.15.0`، وثُبّت `livekit-client@2.25.0`. أضاف حلّهما 17 مدخلاً دون تغيير إصدارات الاعتماديات الموجودة. ثم نجح `npm ci --offline` في مجلد نظيف مستقل باستخدام cache تم ملؤها من npm (85 حزمة). تشغّل اختبارات النسخة المقفلة Vitest 5.1.0 وVite 8.3.8. ظهر تحذير سياسة lifecycle scripts لـesbuild ولم يمنع الفحوص.

## C. حدود البنية

`Today → HumainVoice.tsx → humain.ts → POST /api/voice/session → HUMAIN /agent/sessions → WebRTC`.

يحتفظ WASL بالحالة وسير التشييك الحالي. يقدّم `humain-broker.mjs` جلسة الصوت فقط باستخدام Node HTTP وREST مع `x-api-key`. يستخدم `AgentSession.start()` في المتصفح بيانات اتصال قصيرة الأجل، بينما تمر الوسائط مباشرة إلى HUMAIN عن طريق LiveKit. اختير REST لتجنّب اعتماد خادم إضافي. [توثيق إعداد الجلسة](https://docs.voice.humain.com/en/agent/configure) · [توثيق Browser SDK](https://docs.voice.humain.com/en/sdk/agent-browser).

## D. الأمان والإعداد السري

- يربط الـbroker على `127.0.0.1:4317` ويطابق Host وOrigin مع origin محلي محدد. يتحقق من المسار والطريقة والمحتوى. الطلب الوحيد المنشئ للجلسة هو `POST` بمحتوى `{}`. إعداد agent والـprompt ومخططات الأدوات ثابتة على الخادم، و`web_search: false`.
- الإعداد المحلي `.env.humain.local` يطابق قاعدة `.env.*` في `.gitignore`. تُستثنى `.env.example` فقط وتحوي حقولاً فارغة. لا توجد Git metadata في نسخة العمل لهذا التحقق، لذلك فُحصت قاعدة الاستبعاد مباشرة. يقرأ Node الملف محلياً ويستخدم مفتاحه فقط على عنوان HUMAIN الرسمي المسموح عبر TLS مع رفض التحويلات.
- يُعاد `server_url` و`participant_token` ووقت الانتهاء وحصة ثواني التطبيق فقط، تحت `Cache-Control: no-store`. لا تُسجل الرموز. يحتفظ الخادم بمعرّف جلسة غير سري في الذاكرة للتحقق من انتهاء السابقة، ولا يعتد بتصريح من المتصفح بأن الاتصال انتهى.
- يمنع قفل الإنشاء السباق، ولا تبدأ جلسة جديدة طالما السابقة معلقة أو جارية عند المُزوّد. إذا تعذّر تحديد نتيجة الطلب قبل تسليم رمز يحتفظ الخادم بمهلة حماية. الحصة الافتراضية محاولة إنشاء واحدة لكل تشغيل. حد التطبيق الافتراضي 50 ثانية من إصدار بيانات الاتصال إلى الإنهاء. الإطلاق من المتصفح يتطلب تفعيل flag وأصل loopback والموافقة والنقر. لا إعادة محاولة تنشئ جلسة مدفوعة تلقائياً.
- اختُبرت استجابات مفتاح غائب أو مرفوض، `agent` scope، حساب غير مفعّل، الرصيد، حدود المعدل والتزامن، وفشل الشبكة أو تلف الاستجابة، مع رسائل مصفّاة. اختُبر تشغيل مدخل Node الفعلي على loopback بمفتاح فارغ، فأعاد `503 missing_key` دون اتصال خارجي. لم تظهر قيمة canary اصطناعية في الأصول العامة أو حزمتي البناء. منع Vite أثناء التطوير طلب ملف الإعداد مباشرة أو عبر `/@fs/`.

## E. إمكانات الصوت

Card صغيرة على صفحة Today للمريض الاصطناعي `demo-001` فقط، عبر `VITE_HUMAIN_VOICE_ENABLED=true` على loopback. يُطلب الإذن بعد ضغط Start وقبل طلب جلسة من الـbroker. تعرض البطاقة حالات الاتصال وListening/Thinking/Speaking من callbacks، وتدمج نصوصاً جزئية ونهائية بحسب ID، وتعرض التنبيهات. يدعم المسار رسائل نصية ضمن الحوار المتصل، وكتم وإعادة تمكين الميكروفون، وinterrupt، وتشغيل الرد إذا حجب المتصفح الصوت. التشييك المعتاد بصوته السابق والنص والأزرار متاح مستقلاً.

يملك التطبيق media stream، ويتصل الـSDK دون نشر الميكروفون إلى أن يصبح الاتصال جاهزاً. يوقف End أو timeout أو التنقل أو unmount مسار الصوت المحلي فوراً. الإصدار المثبت من SDK يعيد مقبض الجلسة بعد الاتصال، لذلك عند إلغاء اتصال لا يزال قيد الإنشاء يُلغى طلب الرمز إذا بقي معلّقاً ويُغلق الاتصال عند استلام المقبض إذا تجاوز هذه النقطة. لا تُنشر إشارة الميكروفون من محاولة ملغاة، وتُهمل callbacks القديمة. [دورة حياة الجلسة](https://docs.voice.humain.com/en/agent/events).

## F. أدوات العميل

| الأداة | Schema وإجابة handler |
|---|---|
| `get_demo_context` | يتطلب `{ "scope": "current_demo" }` وحده. يعيد `simulated_day` و`planned_questions` من واجهة Today و`useQuestionPlan` |
| `get_demo_question` | يتطلب `{ "scope": "current_demo" }` وحده. يعيد `available`، و`question_ar` عند وجود سؤال من خطة المريض المعروضة |

تعتمد declarations والواجهة على أسماء متطابقة. تحدد الواجهة نطاق المريض عند تركيب المكوّن، وترفض handlers الحقول غير المصرح بها، ومنها معرّفات السجلات. ثبات `scope` يرفض أيضاً الوسيط غير الصالح إذا طبّعه SDK إلى كائن فارغ. يتلقى SDK ناتج القراءة أو الخطأ، ويُعرض اسم آخر أداة نفّذت قراءة ناجحة. اختُبرت نتيجة القراءة الحقيقية في التطبيق عبر استدعاء handler بمحاكاة SDK، بما يشمل عدم وجود سؤال ورفض المدخلات والجلسة المغلقة. رد الوكيل الحي بحسب نتيجة القراءة معلّق. [توثيق Client Tools](https://docs.voice.humain.com/en/agent/client-tools).
